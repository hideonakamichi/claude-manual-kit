# 公開先・保存先の選び方（目的 → 道具）

「何がしたいか」から道具を選ぶ。名前は**役割が分かる形**で書く（Cloudflare は役割が複数あるため）。

## 道具の役割

| 道具 | 役割 | たとえ |
|---|---|---|
| Cloudflare Pages | サイトを公開する場所 | 店舗 |
| Cloudflare D1 | データを預かる保管庫（SQLite 系） | 小さな倉庫 |
| Vercel | サイトを公開する場所（Next.js に強い） | 店舗 |
| Supabase | クラウド上の DB ＋ ログイン機能 | 貸し倉庫 ＋ 会員証の発行所 |
| SQLite | 手元の1ファイルの DB | 手元のノート |

## 目的 → 道具

| こうしたい | 使う道具 |
|---|---|
| サイトを公開したい（静的） | **Cloudflare Pages（標準）** |
| 記事を並べるだけ | Cloudflare Pages だけ。DB は入れない |
| 問い合わせフォームなど軽い保存 | Cloudflare Pages ＋ D1 |
| 会員ログイン・複数人の同時書き込み | Cloudflare Pages（または Vercel）＋ Supabase |
| 自分用の記録・集計（サイトと無関係） | SQLite（手元。OneDrive 同期フォルダには `.db` を置かない） |

## 標準と例外

- **標準は Cloudflare Pages。** 無料枠が商用で使え、静的配信の帯域が実質無制限
- **Vercel は理由があるとき。** Next.js で機能を作り込む、など。無料枠（Hobby）は非商用向けなので、会社の HP なら有料前提
- **Supabase** の無料枠は、7日間使わないと止まる。運用の間隔を確認して選ぶ（下の「Supabase か Cloudflare か」）
- 標準化しすぎず、案件の規模や要件が変わったら判断し直す。選んだ理由を一言添える

## DB は Supabase か Cloudflare か（DB を使うなら必ず確認する）

DB を使うと決まったら、作り始める前に **Supabase か Cloudflare（D1）か** を本人と決める。人から受け取った仕組み（例: Supabase 前提のスターターキット）でも、そのまま使わずにここで選び直す。

**推奨: Cloudflare D1**（画像は R2 か PC）。下の表で Supabase 側に当てはまるときだけ Supabase。

| 見ること | Supabase | Cloudflare D1 |
|---|---|---|
| アカウント | 新しく作る | HP の公開（Cloudflare Pages）と同じアカウントを使える |
| 無料枠で止まるか | 7日間使わないと一時停止する。週1の実行だとぎりぎり | 止まらない |
| 画像の置き場所 | Storage（カード不要） | R2 はカードの登録が要る。人が手で貼るなら PC で足りる |
| HP から読むとき | 外のサービスとして呼ぶ | Pages Functions から同じ DB をそのまま読める |
| 向いている場合 | 会員ログイン・複数人の同時書き込み・毎日使う・画像をネットに置きたいがカードを登録したくない | HP が Cloudflare・使うのが週1程度・画像は人が手で貼る |

迷ったら、①HP がどこにあるか（Cloudflare なら D1）→ ②使う間隔（7日より空くなら Supabase は避ける）→ ③画像をネットに置く必要があるか（無いなら PC）の順に決める。決めた理由は `design\要件.md` の「道具の構成」に残す。

## 作り方（静的サイト）

- 記事が増え続ける → **Astro**（md を置くだけで一覧とページができる）
- 10本未満で止まる → 手書き HTML でも足りる
- 画面や機能を作り込む → Next.js（公開先は Vercel か Cloudflare Pages）
