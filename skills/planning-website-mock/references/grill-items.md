# グリルで確認する項目（HP づくり）

全22項目。SKILL.md の「聞き方」（1問ずつ・推奨つき・選択肢 A〜E）で聞く。上から順に依存する（目的が決まらないとターゲットが決まらない）。

**全項目の状態を本人に見せる。** 最初に「聞く／決まっている／聞かない（理由）」の表を見せ、モックの前に全項目の状態表で OK をもらう（SKILL.md の②）。

## 1. 基本定義

| 項目 | 聞くこと | 補足 |
|---|---|---|
| 目的・ゴール | 何のための HP か。最終的に何が起きれば成功か | 例: 信頼を得る → 問い合わせが来る |
| ターゲット（ペルソナ） | 誰に見せるか。年代・立場・困りごと | ペルソナ＝想定する読み手の人物像 |
| 競合と差別化 | 似た HP は何か。自分たちは何が違うか | |
| 掲載する内容 | 何を載せるか（記事、商品、会社情報など） | 既存資料があれば先に読む |

## 2. 体験と情報設計

| 項目 | 聞くこと | 補足 |
|---|---|---|
| UX（体験価値）の定義 | 読み終えた人にどう感じてほしいか | UX＝使う人の体験全体 |
| 導線・カスタマージャーニー | 来訪から目的（購入・問い合わせ）までの道筋 | ジャーニー＝その道筋を時系列で描いたもの |
| 情報アーキテクチャ | ページの階層・並べ方・ナビの構造 | |
| 操作性・インタラクション | 押す・めくる・絞り込むときの動き | マイクロインタラクション＝小さな反応の動き |
| アクセシビリティ | 読みやすさ・コントラスト・操作のしやすさの基準 | WCAG AA＝文字と背景の明暗差などの国際基準 |

## 3. デザイン

`参考スタイル.md` の「個性の要素」は**残す前提**で聞く。A（推奨）に引き算（控えめにする・色を減らす・書体を減らす）を置かない。聞くのは「足りない部分をどう埋めるか」（例: 欧文書体しかないので、同じ個性の日本語書体を選ぶ）。

| 項目 | 聞くこと | 補足 |
|---|---|---|
| トンマナ | 雰囲気の言葉・避けたい印象・基調の色 | トンマナ＝トーン＆マナー、全体の統一感 |
| ブランドイメージとの調和 | 既存のロゴ・商品・SNS と合っているか | |
| グラフィック要素 | 形・画像の切り抜き・余白の使い方 | |
| タイポグラフィ | 書体・行間・1行の文字数 | |
| デザイントークン | 色・余白・角丸・影を統一して定義するか | トークン＝デザインの共通部品の値 |

## 4. 作る箱（ページ構成・機能）

| 項目 | 聞くこと |
|---|---|
| ページ構成 | トップ・一覧・詳細・会社情報など、作るページ |
| 共通部品 | ナビ、フッター、共通の行動ボタン（CTA） |
| 記事まわり | 一覧、絞り込み、カード表示、詳細の読みやすさ |
| 問い合わせ | フォームの項目、同意、送信完了ページ |

## 5. 運用・技術

| 項目 | 聞くこと | 補足 |
|---|---|---|
| デバイスの優先順位 | PC とスマホのどちらを優先するか。見る幅の基準 | レスポンシブ＝画面幅に合わせて並びが変わる設計 |
| 更新の運用 | 誰が、どのくらいの頻度で記事を足すか | CMS＝更新用の管理画面。要るかも聞く |
| 予算・納期 | かけられる費用と時期 | |
| ドメイン・公開先 | 独自ドメインの有無、公開先の方針 | → [tool-selection.md](tool-selection.md) |

## 聞かなくてよいこと（ただし表には理由を書いて見せる）

- コードや資料で分かること → 「決まっている（出どころ）」と書く
- 案件に無関係な項目（例: フォームが要らないのに項目を聞く） → 「聞かない（理由）」と書く
