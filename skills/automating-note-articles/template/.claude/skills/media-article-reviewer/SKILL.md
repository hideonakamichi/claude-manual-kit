# note 記事の審査（レビュアー専用）

> **先に `media.config.json` を Read する。** この手順の `{質問役}` `{解説役}` `{会社}` `{読者}` などは、その値に置き換えて読む（対応は media-article-writer の冒頭と同じ）。

note に出る前の最後の砦。ライター自身のチェックには盲点があるので、**第三者として全文を見る**。
{会社}は実在の会社。**会社について本当でないことが1つでも残ったら、会社の発信として外に出てしまう。**

## 制約

- 存在しない URL・事実を記事に足さない
- 直すのは「書き方の違反」と「事実の誤り」だけ。文体・言い回しの好みは直さない

## 流れ

```
1. 読む: python scripts/db.py get {id}（article_md / research_notes / review_log）
2. 出典の事前検証（だめなら即差し戻し。中身の審査に進まない）
3. 機械チェック: python scripts/check_article.py --id {id}
4. 22項目を全部見る
5. 引用との照合（記事の数字・言い切り・会社と商品の話 ↔ quotes ↔ facts）
6. 判定
   - 自分で直せる（下の表）→ 直して保存 → 3 からやり直し
   - 直せない → 差し戻し（行番号と直し方を具体的に）
   - 全部 OK → 合格。reviewer_verifications を足す
7. 審査結果を review_log に足す → 編集長に返す
```

## 2. 出典の事前検証

次のどれかなら **即差し戻し**:

1. research_notes が空
2. sources が3件未満
3. {信頼できる出典} が1件も無い
4. 記事に数字があるのに、対応する quote が無い

## 4. チェックリスト（22項目）

番号は全テイスト共通。テイスト（**記事の style**。空なら `article_style`。check_article の結果にも出る）で中身が変わる項目は、ライターの手順「テイストごとの形」の表で読む。話者あり＝dialogue・interview、地の文＝essay・story・howto・documentary。

### A. 形（5）

- [ ] **1.** 始まり方（E01）。dialogue＝`**{質問役}**: ` の質問／interview＝リード文のあと `**{質問役}**: ` の質問／地の文＝読者への問いか場面（「この記事では」で始めない）
- [ ] **2.** 型どおり（E02）。話者あり＝{質問役}は質問、{解説役}は解説で逆転が無い／地の文＝表の「中身の順番」になっている（howto は :::steps がある・E07）
- [ ] **3.** 地の文の置き場所（E03）。dialogue＝発言の外に無い／interview＝最初の `##` より前のリード文だけ・3段落まで／地の文＝見ない
- [ ] **4.** リストは :::steps / :::point / :::caution の中だけ（E04）
- [ ] **5.** `**名前**:` は話者だけ・コロンは半角。地の文のテイストでは1つも無い（E06）

### B. note で表示できる書き方（5）

- [ ] **6.** 表・水平線・`<mark>`・H1 が無い（E05・E01）
- [ ] **7.** 箱の開き閉じが合い、種類は point / caution / steps だけ。point が1つ以上（E07）
- [ ] **8.** 話者あり＝1発言6文まで／地の文＝1段落4文まで（E08）
- [ ] **9.** 見出し画像1枚 + 図解1枚以上、図解は `##` のすぐ次（E13）
- [ ] **10.** 画像のファイル（image_mode が manual なら指示文）が全部あり、ネットの画像を使っていない（E14）。manual なら指示文だけで画像が作れる中身か。指示文に image_style と「避けること（image_avoid）」があり、image_reference があれば見本の1行がある

### C. 中身（6）

- [ ] **11.** 見出しのつなぎ（各 `##` の最初と最後の発言。地の文なら段落）がある
- [ ] **12.** AI 臭い言い回しが無い（E09）
- [ ] **13.** 本文 {字数}字・`##` が{見出し数}個（E12）
- [ ] **14.** 「！」{！の回数}回（地の文のテイストは exclamations_prose）・「(笑」2回まで（E15）
- [ ] **15.** 相対の時制が無い（E11）
- [ ] **16.** 読者が家で試せる具体（手順・分量・タイミングのどれか）がある

### D. 言えないこと・リンク（3）

- [ ] **17.** {言えないこと} が無い（E10）。機械が見落とす言い換え（食品なら「体が喜ぶ」「ミネラルで元気に」等）も目で見る
- [ ] **18.** 商品へのリンクは {商品} の url だけ（E16）
- [ ] **19.** 記事中の全 URL が 200（`python scripts/web.py status URL`）

### E. 事実（3）

- [ ] **20.** 出典の事前検証（上の2）が通っている
- [ ] **21.** 記事の数字・言い切った一般論が、全部 quotes の文と合っている（意味が変わっていない）。怪しいものは `python scripts/web.py read URL` で元のページを読み直す
- [ ] **22.** 会社・商品について書いたことが、全部 `facts/確かめた事実.md` か商品ページの引用にある。「提案としてなら書けること」を事実のように書いていない。interview・documentary は、発言と場面が全部 `interview_file`（取材メモ）にある（メモが無ければ E17 で即差し戻し）。story の場面は例え話と分かり、実在のお客さんの声・実際の出来事のように書いていない

## 6. 直すか、差し戻すか

| 種類 | 例 | どうする |
|---|---|---|
| 書き方（自分で直す） | 全角コロン・AI 臭い言い回し・相対の時制・「！」の数・表を箱に変える・1か所の効能表現を消す | 直して `work/article_{id}.md` に書き、`python scripts/db.py save-draft ...` で保存 |
| 中身（差し戻す） | 話者の逆転・テイストの形が違う・出典不足・quote の無い数字が多い・会社について確かめていない話・取材メモに無い発言や場面・画像が無い・長さが大きく外れる | 差し戻し |

## 合格のとき

1. research_notes に検証結果を足す（`work/notes_{id}.json` に今の research_notes を書き出して足し、`save-draft` で保存）

```json
"reviewer_verifications": [
  {
    "reviewer": "media-reviewer",
    "verified_at": "YYYY-MM-DDTHH:MM:SS+09:00",
    "checks": [
      { "claim": "記事中の言い切り", "source_url": "https://...", "verdict": "confirmed" }
    ],
    "overall_verdict": "approved"
  }
]
```

2. `work/review_{id}.json` に `{"at": "日時", "verdict": "approved", "round": n}` を書き、`python scripts/db.py add-review {id} work/review_{id}.json`

```
✅ 合格
記事ID: {id}
タイトル: {title}
- A. 形: ✅ / B. note の書き方: ✅ / C. 中身: ✅ / D. 言えないこと・リンク: ✅ / E. 事実: ✅
直した所: {あれば。無ければ なし}
```

## 差し戻しのとき

`work/review_{id}.json` に `{"at": "日時", "verdict": "rejected", "round": n, "items": [...]}` を書いて `add-review` してから返す。

```
❌ 差し戻し
記事ID: {id}

## NG
1. **#2 話者の逆転**
   - 場所: L14「**{解説役}**: それって家でもできるんですか？」
   - 直し方: この発言を{質問役}に移し、{解説役}の答えを続ける
2. **#22 確かめていない会社の話**
   - 場所: L40「創業から〜」
   - 直し方: facts に無いので、この文を消す
```

## 判定の原則

- 主観を入れない。チェックリストで機械的に
- 「だいたい OK」で合格にしない
- ライターの言い分は聞かない
- 指示は「L23 を消して〜にする」のように具体的に

## 自己診断（quality_check に書く）

- ✅/❌ 出典の事前検証を最初にした
- ✅/❌ check_article を実行した
- ✅/❌ 22項目を全部見た
- ✅/❌ 会社・商品の話を facts と1つずつ照合した
- ✅/❌ 直す / 差し戻すを表のとおりに分けた
- ✅/❌ review_log に結果を足した（合格なら reviewer_verifications も）

## ルールを足すとき

チェックリストに番号で足し、`scripts/check_article.py` に E番号の検出を足し、ライターの手順（`media-article-writer`）にも同じことを書く。3つそろわないルールは守られない。
