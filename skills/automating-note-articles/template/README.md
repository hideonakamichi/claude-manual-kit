# note 記事キット（オウンドメディアの記事を自動で作る）

会社の note 記事を、AI の3人チーム（編集長・ライター・レビュアー）が **審査の合格まで自動で** 作るキット。
公開した記事は、HP のトップに自動で並ぶ（HP 制作キットとつないだ場合）。

正本はスキル `automating-note-articles` の `template\`。案件にはコピーして使う。

## 2つのキットの関係

| キット | 何をする | 正本 |
|---|---|---|
| ① HP 制作キット | 参考サイト → 22項目 → モック → 素材 → 実装・公開 | スキル `planning-website-mock` |
| ② note 記事キット（これ） | ネタ → 執筆 → 審査 → note 用の下書き → HP に自動で出る | スキル `automating-note-articles` |

別々に使える。①だけ（記事は手書き）、②だけ（HP なし・note だけ）でも動く。つなぐ場所は下の「HP キットとのつなぎ方」。

## 流れ

```
 人 ── ネタを選び、すすめのテイストを確かめる（topics.py adopt / style）
  ↓
 編集長 ── 書く待ちのネタを選ぶ（無ければネタ候補を出して通知）
  ↓
 ライター ── 調べる（Jina）→ 書く → 画像（Gemini・PC に保存）→ DB（Cloudflare D1）
  ↓
 レビュアー ── 22項目で審査 ──NG→ ライターへ差し戻し（書くのは最大3回＝直し2回。3回目の差し戻しで見送り）
  ↓ 合格
 編集長 ── note下書き\ に書き出し → 完了通知（Gmail・Slack・Discord・Chatwork・LINE から1つ）
  ↓
 人 ── 下書き.html をブラウザで開いて note に貼り、公開（topics.py posted）
  ↓
 HP ── トップの「note の新着」に自動で出る（RSS。HP 側の作業なし）
```

## 案件ごとに変えるのは2ファイルだけ

| ファイル | 中身 | 誰が書く |
|---|---|---|
| `media.config.json` | 会社名・読者・目的・トーン・記事のテイスト・話者か書き手・字数・商品と URL・信頼できる出典・言えないこと・画像の見た目と見本・通知の件名・DB の名前 | Claude が本人に聞いて書く |
| `facts\確かめた事実.md` | 会社・商品について記事に書いてよい事実（出所つき） | 本人が確かめたものだけ |

3人の手順書（`.claude\`）とスクリプト（`scripts\`）は、どの案件でも同じ。案件の値を手順書に直接書かない（書くと、次の案件で書き換え漏れが出る）。

## この案件で決めたこと

キットを入れたときに決めたことと、その理由を書く（あとで蒸し返さないため）。

| こと | 理由 |
|---|---|
| note への公開は人がやる | note に投稿用の公式 API が無い。会社の発信なので、出す前に人が見る（キットの前提） |
| note へ貼るのも人（ブラウザ自動操作で下書き保存まで自動にする案は見送り） | 公式 API が無いので、自動にするにはブラウザ操作か非公式の裏口しかない。週1本なら手で貼っても数分で、作る手間と note の画面が変わるたびに直す手間のほうが重い。本数が増えたら考え直す（キットの前提） |
| 会社・商品について書けるのは `facts\確かめた事実.md` だけ | 本当でないことを会社の名前で出さない（キットの前提） |
| 記事の保存先: （D1 / Supabase） | （理由） |
| 使うテイスト: （対話 / インタビュー / 読み物 / ストーリー＋解説 / ノウハウ / 密着 から複数）・既定: （）・字数 | （本人の選択。見本を見て選んだ理由）。記事ごとに編集長がすすめ、本人が採用のときに確かめる |
| 画像のテイスト: （例: フラットな線画・避けること: 水彩）・見本: （HP の URL など） | （本人の選択。HP とそろえるため など） |
| 言えないこと | （業界の理由） |

## サーバーの選び方（作る前に必ず確認する）

記事の保存先は **Supabase か Cloudflare か** を、作り始める前に本人と決める。人から受け取った仕組みが Supabase 前提でも、そのまま使わない。判断は、HP 制作キット（別配布）に同じ表がある。無ければ次の順で決める: ①HP がどこにあるか（Cloudflare なら D1）→ ②使う間隔（7日より空くなら、無料枠が一時停止する Supabase は避ける）→ ③画像をネットに置く必要があるか（無ければ PC）。

**推奨: Cloudflare D1（記事）＋ 画像は PC**。表の「向いている場合」で Supabase 側に当てはまるときだけ Supabase。

| 見ること | Supabase | Cloudflare D1 |
|---|---|---|
| アカウント | 新しく作る | HP の公開（Cloudflare Pages）と同じアカウントを使える |
| 無料枠で止まるか | 7日間使わないと一時停止する。週1の実行だとぎりぎり | 止まらない |
| 画像の置き場所 | Storage（カード不要） | R2 はカードの登録が要る → note に手で入れるなら PC で足りる |
| HP に記事を出すとき | 外のサービスを HP から呼ぶ | Pages Functions から同じ DB をそのまま読める |
| 向いている場合 | 毎日動かす・画像をネットに置きたい・カードを登録したくない・管理画面で表を見たい | HP が Cloudflare・週1程度・note に手で貼る |

迷ったときの決め方: **HP がどこにあるか**（Cloudflare なら Cloudflare）→ **実行の間隔**（7日より空くなら Supabase は避ける）→ **画像をネットに置く必要があるか**（無いなら PC）。

## HP キットとのつなぎ方

同じ案件フォルダに並べて置く。

```
案件フォルダ\
├── design\        ← ① HP キット（要件・参考スタイル・素材）
├── site\          ← ① HP 本体
├── functions\     ← ① HP の小さなプログラム（note の新着を読む: api\note.js）
└── note-agent\    ← ② note 記事キット（このフォルダ）
```

| つなぎ目 | ① HP キット側 | ② note 記事キット側 |
|---|---|---|
| 読者・目的・トーン | `design\要件.md` の目的・ターゲット・UX | `media.config.json` の reader / goal / tone に写す |
| 会社・商品の事実 | `design\素材\素材リスト.md` の ✅ 受け取り済み | `facts\確かめた事実.md` に写す（🟨 仮は写さない） |
| 商品のリンク | 素材リストの販売先 URL | `media.config.json` の products |
| 画像の色とタッチ | `design\参考スタイル.md` の色・公開した HP の URL（公開前ならモックのスクリーンショット） | `media.config.json` の image_style / image_avoid / image_reference |
| note のアカウント | Cloudflare Pages の環境変数 `NOTE_USER` | `media.config.json` の note_user（同じ値にする） |
| 記事が HP に出る | `functions\api\note.js` が note の RSS を1時間ごとに読む | 人が note に公開するだけ。HP の公開し直しは要らない |
| Cloudflare のアカウント | HP の公開（wrangler でログイン） | 同じアカウント。ただし鍵は別（D1 だけ触れる API トークン） |

**つなぐときの順番:** ① で HP の22項目と素材が決まる → その値を ② の `media.config.json` と `facts` に写す → ② を回す。② から ① の中身（`site\` など）は書き換えない。

**将来 HP の中に記事ページを出したくなったら:** D1 の `articles`（status = posted）を、HP の Pages Functions から読む。同じ Cloudflare アカウントなので、DB をつなぐ設定を足すだけで済む（そのときに ① のスキルで設計する）。

## フォルダ

```
note-agent\
├── README.md               ← このファイル
├── media.config.json       ← 案件ごとの値（ここだけ書き換える）
├── .env.local.sample       ← 合鍵の書き方（コピーして .env.local に）
├── facts\確かめた事実.md     ← 会社・商品で書いてよいこと（人が増やす）
├── facts\取材メモ.md         ← インタビュー風・密着のときだけ。人が実際に聞いた言葉・見た様子
├── .claude\
│   ├── settings.json       ← 許可する操作
│   ├── agents\             ← 3人の役割（media-editor / media-writer / media-reviewer）
│   └── skills\             ← 3人の手順書と共通の起動・終了（agent-bootstrap）
├── scripts\
│   ├── db.py               ← D1（DB）の読み書き
│   ├── topics.py           ← 人が使う: ネタを選ぶ・公開済みにする・一覧
│   ├── web.py              ← Jina で調べる・URL の生存確認
│   ├── gen_image.py        ← 画像の用意（gemini: 画像を作る／manual: 指示文を作る）
│   ├── check_article.py    ← 記事の機械チェック（E01〜E17。テイストで切り替わる）
│   ├── export_note.py      ← 合格記事を note 用の下書きに
│   ├── notify.py           ← 完了通知・失敗の知らせ（送れなければ work\未送信\ に残して次に送り直す）
│   ├── reflection.py       ← 振り返りの記録（手元の SQLite）
│   └── run-agent.ps1       ← 編集長を1回動かす（タスク スケジューラから）
├── d1\schema.sql           ← DB の表（articles）
├── images\                 ← Gemini の画像・画像の指示文（自動でできる）
├── work\                   ← 途中のファイル（消してよい）
├── note下書き\              ← できあがった下書き（自動でできる）
└── logs\                   ← 自動実行のログ（自動でできる）
```

## はじめの準備（1回だけ）

1. **サーバーを決める**（上の「サーバーの選び方」。推奨つきで本人に確認）
2. `.env.local.sample` をコピーして `.env.local` にする
3. **通知**（設定より先に済ませる）: 毎日開くものから通知先を1つ選び（下の表）、`.env.local` の `NOTIFY_CHANNEL` とその欄を埋める → `python scripts\notify.py test` → **届いたのを本人が確かめるまで次へ進まない**。自動実行は通知の設定が無いと記事を書かずに止まる（結果に誰も気づけないため）
4. `media.config.json` と `facts\確かめた事実.md` を案件に合わせる（HP キットがあれば「つなぎ方」の表から写す）
5. **Cloudflare**: アカウント ID と API トークン（権限は「アカウント / D1 / 編集」だけ）を `.env.local` に → `python scripts\db.py init`（DB と表ができる）
6. **Gemini**: https://aistudio.google.com/apikey でキー → `.env.local` に
7. **Jina**（推奨・無料のキー）: https://jina.ai でキー → `.env.local` に → `python scripts\web.py key` が「あり」。無くてもページは読めるが、検索ができず出典集めで詰まりやすい

### 通知先の選び方（条件は変わるので、案内する前に公式で確かめる）

| 通知先 | 準備 | お金 | ハードル |
|---|---|---|---|
| Discord | チャンネルの設定 → 連携サービス → ウェブフック → URL を貼る | 無料 | 低い |
| Slack | 通知用チャンネルで Incoming Webhook を作り URL を貼る | 無料プランで可 | 無料プランはアプリ10個まで。会社の Slack は管理者の許可が要ることがある |
| Gmail | 2段階認証をオン → アプリ パスワード（16文字）を作る → 貼る | 無料 | 手順が多め |
| Chatwork | API トークンと受け取るチャットの番号を貼る | **有料プラン（スタンダード以上）** | 組織のアカウントは管理者の承認が要る |
| LINE | LINE公式アカウントを作り Messaging API を有効に → トークンと自分のユーザーID を貼る | 無料プランは月200通まで（週1なら足りる） | 高い（公式アカウントづくりと ID 調べ） |

- 毎日開くものの中で、ハードルが一番低いものをすすめる（届いても見ない場所では意味がないため）
- 送れなかった通知は `work\未送信\` に残り、次に編集長が起動したとき送り直す
- 自動実行が途中で止まったとき（時間切れ・起動できない・最後まで終わらない）は、run-agent.ps1 が同じ通知先に「失敗」を1通送る
- メールや Slack の中の file:/// リンクは押せないことが多い。場所をエクスプローラーの上の欄に貼って Enter

## ふだんの使い方

| やりたいこと | どうする |
|---|---|
| 1回動かす | このフォルダで Claude Code を開き「編集長を起動して1周回して」 または `powershell -ExecutionPolicy Bypass -File scripts\run-agent.ps1` |
| ネタを選ぶ | `python scripts\topics.py list` で候補とすすめのテイストを見て、`python scripts\topics.py adopt 3 5 7`（使わないものは `drop`） |
| テイストを変える | `python scripts\topics.py style 3 essay`（書く前なら、採用の前でもあとでも） |
| 状態を見る | `python scripts\topics.py list` |
| 画像を入れる（manual のとき） | `note下書き\{番号}\下書き.html` の指示文で画像を作り、決まった名前で `note下書き\{番号}\images\` へ → 「{番号} の下書きを作り直して」 |
| 下書きを開く | Claude に「{番号} の下書きを開いて」（`python scripts\export_note.py {番号} --open`）。ブラウザで開き、画像が足りなければ置き場所のフォルダも開く |
| note に貼る | `note下書き\{番号}\下書き.html` を**ブラウザで**開き（エクスプローラーでダブルクリック）、ボタンを①から順に押して note で Ctrl+V（図解のあとは Enter を1回） |
| 公開した | `python scripts\topics.py posted 5 https://note.com/...` |
| 見送りを書き直す | `python scripts\topics.py requeue 8` |
| 会社の事実を足す | `facts\確かめた事実.md` に出所と一緒に書く |

## ルールを足すとき

「必ず〜する」を足すときは、**ライターの手順書・レビュアーのチェックリスト・`check_article.py` の3か所に同じ番号で** 入れる。どれかが欠けると、書いてあるのに守られないルールになる。
案件だけの値（言えない言葉・字数など）は手順書ではなく `media.config.json` に足す。
